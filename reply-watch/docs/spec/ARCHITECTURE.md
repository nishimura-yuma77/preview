# アーキテクチャ：返信待ちの管理

| 担当 | 判断すること | 受け渡すもの |
| --- | --- | --- |
| Slack ブリッジ（Bolt / Socket Mode） | 既存の依頼受付条件を満たす `@Bot` 宛て投稿と、その会話に属する Slack 投稿を識別する。最終回答と進捗を区別できるのは送信側である。 | 投稿成功時の最終回答、または同じスレッドの人の新規返信を、Slack の投稿時刻付きで内部 API に通知する。状態や完了命令は送らない。 |
| reply-watch（Node.js） | 通知の入力検証、追跡開始・完了・再開の判断、返信待ち一覧の生成。 | SQLite の唯一の読み書き主体。読取 API にチャンネル名と最終回答のパーマリンクを返す。 |
| nginx / ブラウザ | nginx は HTTPS と Basic 認証を担当。ブラウザは一覧を5秒間隔で取得する。 | 読取失敗は空一覧と区別し、直前の一覧と更新エラーを表示する。 |

### ブリッジとの境界

ブリッジは受理したメンションのチャンネル ID・親投稿時刻を会話に紐づけ、再起動後も識別できるよう保持する。起点がスレッド内のメンションなら、その親投稿時刻を使う。人の返信の通知判定は、Bot に新しい依頼を出せる利用者の判定より先に行う。メンションなしの第三者の返信も完了の根拠になり、依頼権限は変わらない。通常のチャンネル投稿、編集・削除、リアクション、Bot の進捗や他 Bot の投稿は対象外。分割した最終回答は全体の投稿成功時に、末尾の回答投稿を一度通知する。

### 状態の決定

アプリ層は対象スレッドごとに最終回答と人の返信の最新投稿時刻を別々に持つ。通知の受信時刻ではなく Slack の投稿時刻で比較する。

| 最新の最終回答 | 最新の人の返信 | 追跡項目と表示 |
| --- | --- | --- |
| 未着 | あり | 比較用の返信時刻だけ保持。追跡項目はまだ成立せず、非表示 |
| あり | なし、または回答より前 | 返信待ち（`pending`）。最新回答へのリンクを表示 |
| あり | 回答より後 | 完了（`done`）。履歴行を残して非表示 |

各種別で古い通知と同時刻の再送を無視し、時刻とリンクを同一トランザクションで確定する。たとえば返信→回答の順に配送されても、Slack 上で返信の方が新しければ最初から完了になる。ブリッジは一時的な配送失敗を再送できるよう通知を保持し、再送時は同じ投稿時刻を使う。

### 配置・公開範囲

`/srv/reply-watch/` は `/srv/previews/` の隣に置く。nginx に読み取り専用でマウントするのは `public/` のみ。`/task` の画面、配下の静的資産、`GET /task/api/pending` に Basic 認証を適用し、API レスポンスは `no-store` とする。Node.js はループバックで待ち受ける。nginx からの API 転送は読取先だけに限定し、書き込みは同一ホストのブリッジから Bearer トークン付きで直接呼ぶ。

| 相対パス | 内容 |
| --- | --- |
| `src/server.mjs`・`src/routes.mjs` | 起動・HTTP 境界 |
| `src/task-service.mjs`・`src/task-store.mjs` | アプリ層・SQLite アクセス |
| `public/` | 一覧画面と読取 API を呼ぶスクリプト |
| `migrations/`・`data/tasks.sqlite` | スキーマ変更と非公開の実行時データ |
